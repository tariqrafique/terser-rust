# Fixture board triage

`--set fixture` runs every `test/compress` case with its own options, the way terser's `test/compress.js` does (`harness/lib/compress-runner.mjs`: `Compressor` with `false_by_default`, `figure_out_scope(mangle)`, `mangle_names`, `mangle_properties`, `OutputStream(format)`). The Rust board passes the case's `fixture` JSON (`{compress, mangle, format, parse, rename}`, `compress.defaults: false` written when the test omitted it) to `terser::minify`.

Board at `e0d50d6`: **2109/2671, 562 failing.** No failure is an error on the terser side; the port panics on 3 cases and fails to parse 11 TypeScript ones.

## Method

1. `./target/fast/harness board --set fixture`, failing ids from `harness/.board-cache/failed.tsv`.
2. For every failing case the oracle pipeline (`runFixture`) was rerun with the parts the port does not read taken out: `format` set to `{}`, `rename` off, `mangle` cut to `{toplevel, module}` (all `scope::MangleOptions` has), and every compress option that `compress/src` never reads deleted (that gives terser's default, which is what the port hard-codes). The port was run on the same reduced options with `target/fast/examples/try`.
   - Reduced terser == reduced port: the failure is only the ignored options (**class a**). Each ignored option was then removed alone; the cluster is the one whose removal reproduces the port's output.
   - Otherwise there is a compressor difference left (**class b**). For those, each read compress option was toggled on both sides (each of 19 options added, `toplevel` and `passes` removed, `defaults: true`); an option whose toggle makes the two agree points at the code path. Then `tools/trace-diff.sh` on samples, and reading the diffs.
3. Every case with `expect_stdout` whose port output is not an error (227) was run under node, terser's output and the port's side by side (a `-r` prelude defines `id` and `leak` as terser's sandbox does). Every port output was also parsed with terser's parser.

`toplevel`-dependent paths stand out: the default board never sets `toplevel`, so 46 failures there (F10) are compressor bugs the default board cannot see. Likewise `defaults: false` with a handful of options takes paths the default board never takes (F2, F6).

## Reproducing

- `./target/fast/harness board --case compress/<id> --set fixture` prints both outputs.
- The case's options are `fixture` in `harness/corpus/compress/cases/<id>.json`; `target/fast/examples/try "$(jq -c .fixture <case>.json)" < input.js` runs the port with them, and `tools/trace-diff.sh in.js '<that JSON with mangle false>'` works on them (its terser side is `minify`, which matches `Compressor` when `compress.defaults` is `false`).
- The oracle pipeline with modified options: `runFixture(input, spec)` from `harness/lib/compress-runner.mjs`, with `spec = specFromCase(caseJson)` edited (`spec.format = {}`, `delete spec.options.<key>`).
